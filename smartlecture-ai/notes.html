Operating Systems: Virtual Memory, Paging & Segmentation

Duration: 54 mins · Processed: Today, 10:30 AM · Prof. Sharma (BCA Dept)
Generate Quiz
Executive AI Summary

This lecture covers modern memory hierarchy, focusing on how Virtual Memory decouples the logical address space seen by programmer processes from physical RAM frames. Key topics explored include Paging, Page Tables & Multi-level Paging, Translation Lookaside Buffers (TLB), and page replacement strategies to minimize Thrashing.

Overview

In traditional contiguous memory allocation, an entire program had to be brought into main physical memory before execution could begin. However, realistic enterprise applications frequently exceed physical RAM capacity.

Virtual memory solves this bottleneck by loading only required portions of an executable into physical memory pages on demand, keeping inactive code and data on secondary storage (swap space). This permits multiprogramming with significantly higher degree of concurrency.

Key Concepts

  • Logical vs Physical Address Space: A logical address is generated by the CPU during instruction fetch/execution, whereas a physical address refers to actual hardware memory locations in RAM.
  • Pages and Frames: Logical memory is partitioned into fixed-sized blocks called Pages. Physical RAM is partitioned into equal-sized blocks termed Frames (typically 4 KB).
  • Memory Management Unit (MMU): Hardware unit between CPU and memory bus translating virtual page numbers ($p$) to physical frame numbers ($f$).
  • Demand Paging: Pages are brought into main memory only when referenced by the CPU during execution.

Important Points for University Exams

  • No external fragmentation exists in pure paging because any free frame can accommodate any process page.
  • Internal fragmentation may occur on the last page of a process (average half page loss = 2 KB for 4 KB pages).
  • Effective Memory Access Time ($EMAT$) formula:
    EMAT = (Hit Ratio × (TLB_access + RAM_access)) + ((1 - Hit Ratio) × (TLB_access + 2 × RAM_access))
  • Page fault servicing requires trapping into OS kernel mode, generating disk I/O, updating the frame table, and restarting the faulted instruction.

Core Definitions

Translation Lookaside Buffer (TLB) A high-speed associative hardware cache integrated into the CPU's MMU that stores recent virtual-to-physical address mapping translations to prevent double memory lookups.
Thrashing A catastrophic state where an operating system spends more CPU time swapping pages in and out of backing store than actually executing instruction cycles, causing throughput to plummet toward zero.
Belady's Anomaly The counterintuitive scenario where increasing the number of physical page frames allocated to a process increases rather than decreases the number of page faults (observable under the FIFO page replacement policy).

Address Translation Example

Consider a system with 32-bit logical addresses, a page size of 4 KB ($2^{12}$ bytes), and physical memory of 1 GB.

// Logical Address Breakdown (32-bit CPU): // [ Page Number (p): 20 bits ] | [ Offset (d): 12 bits ] // 2^20 pages = 1,048,576 page entries per process! unsigned int translate_address(unsigned int virtual_address) { unsigned int page_number = virtual_address >> 12; unsigned int offset = virtual_address & 0xFFF; // 4095 mask // Check TLB or Page Table int frame_number = lookup_page_table(page_number); if (frame_number == -1) { trigger_page_fault(page_number); // Kernel Trap } unsigned int physical_address = (frame_number << 12) | offset; return physical_address; }

Exam Important Questions & Model Answers

Q1: Differentiate between Paging and Segmentation with diagrams. (8 Marks)
Model Answer:
1. Paging: Non-contiguous, fixed-size blocks (pages & frames) determined strictly by hardware architecture. Invisible to programmers. Avoids external fragmentation.
2. Segmentation: Variable-sized logical units reflecting user modular view (Functions, Arrays, Stack, Symbol table). May suffer from external fragmentation.
3. Modern architectures (x86_64) implement paged segmentation combining protection with zero external fragmentation.
Q2: Explain the steps involved in handling a Page Fault interrupt. (6 Marks)
Model Answer:
1. CPU references memory; MMU detects valid-invalid bit is 0 in page table.
2. Internal hardware trap to OS kernel.
3. OS verifies access legality; finds free frame in RAM.
4. Disk I/O scheduled to read page from swap partition into the designated frame.
5. Page table updated (valid bit set to 1, frame number registered).
6. Faulted instruction restarted seamlessly.
Q3: How does the Working Set Model prevent Thrashing? (6 Marks)
Model Answer:
Based on locality of reference: $WSS_i$ represents the number of unique pages referenced in the most recent $\Delta$ memory references. If total demand $D = \sum WSS_i > \text{Total RAM Frames}$, thrashing occurs. The OS suspends one or more lower-priority processes to preserve throughput for remaining tasks.
